## Task 1 - Financial AI Equity Research Assistant

**Architectural decisions.** Deterministic and LLM logic are separated: `data_pipeline.py` (Task 1A) is pure pandas/numpy with no API calls beyond price/news I/O, letting all five indicators be unit-tested against synthetic data with zero LLM dependency. `llm_reasoning.py` (Task 1B) is the only file that talks to the model. The LLM vendor sits behind a single client class; I built against Groq, then swapped to OpenRouter mid-project, and the swap touched only `config.py` and that class. Every LLM response is validated against a Pydantic `BaseModel`, with one retry that feeds the validation error back to the model — turning "almost-JSON" into a hard boundary. Headline classification moved from one call per headline to a single batched call after sequential requests tripped free-tier rate limits; this exposed a fixed token budget that truncated the JSON array for larger batches, fixed by scaling `max_tokens` to headline count. The client also treats per-minute 429s (worth exponential backoff) as distinct from OpenRouter's daily quota (50/day free), which fails fast instead of retrying pointlessly. The Colab clone cell now uses an absolute path with `git pull`, after a relative-path clone caused stale nested directories on re-run.

**Would improve with more time:** backtest the Buy/Hold/Sell signal across historical windows rather than a single point-in-time call; cache sentiment classifications by headline text; add an LLM-as-judge pass on signal justifications.

**Limitations:** `yfinance`'s `.info` endpoint is fragile, so fundamentals omit missing fields rather than failing the pipeline; 52-week high/low approximates one year as 252 trading days; free-tier rate limits (per-minute and per-day) were the dominant practical obstacle, shaping the batching/backoff/fail-fast design above; indicator correctness was validated against synthetic data and manual arithmetic, not a reference library, since TA-Lib is disallowed.

## Task 2 - Domain-Specific Fine-Tuning Pipeline

**Architectural decisions.** I chose an AI code-review assistant over a generic chatbot, both to avoid the rubric's 5/30 cap on generic tasks and because it's a domain I can grade myself. The teacher model (Llama-3-70B class via Groq, migrated to `openai/gpt-oss-120b` after Groq decommissioned the original models mid-project) is a different family/size from the fine-tuned student (Phi-3-mini-4k-instruct), avoiding "grading your own homework." QLoRA (4-bit NF4) was necessary, not optional, since a free T4 can't full-fine-tune even a 3.8B model at usable sequence lengths. Every LLM call — generation, inference, judging — is JSON-validated; this was the largest source of pipeline fragility and skipping it would have silently corrupted results.

**Qualitative analysis.** LLM-as-judge scores improved on all three dimensions (issue_detection 1.30→1.80, json_validity 4.40→4.70, actionability 2.60→2.90), with a smaller BERTScore F1 gain (0.884→0.888). Manual review of 10 fine-tuned outputs found 6 fully correct, 10% hallucinated, correctly catching non-obvious issues like a missing thread-join. I did not run the same review on base-model outputs, so I lack a matched-pair citation — the clearest evaluation gap. The dominant failure mode is schema non-conformance, not hallucination (most outputs used out-of-enum categories/severities), while json_validity still scored high — suggesting the judge under-penalizes schema drift. The one hallucination and one near-miss both trace to under-represented security scenarios.

**Next steps:** reject/regenerate teacher examples that already drift from the schema; rebalance sampling toward security-critical patterns; run the matched base-model manual review.

**Limitations encountered:** a Colab environment mismatch forced relaxing `transformers`/`tokenizers` pins to floors; TRL's `SFTTrainer` API changed mid-project, requiring a rewrite against the installed version; `merge_and_unload()` failed on the 4-bit quantized model, fixed by reloading the base model in bf16 and merging onto that; an LLM-as-judge cell initially returned a false all-zero result from silently swallowed JSON-parse failures, caught only by printing the failure count; Groq's daily token cap constrained data generation, mitigated by batching and checkpointing.
